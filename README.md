# 家庭能源管理系統 — 顯示與操作介面（HEMS UI）

> 《基於發電量與負載預測之家庭能源管理系統》（組別 A04-1151）

以 **React + Vite** 製作的能源管理儀表板前端，對應計畫書第三章「顯示及操作頁面」。

**負載與太陽能已接真實資料**：RF 隨機森林的不可轉移負載滾動預測、LSTM 的太陽能日前預測
都存在 MongoDB Atlas，由預測端匯出成靜態快照隨網站部署（原因見下方「資料來源」）；
天氣是同一天台北的 ERA5 再分析資料。GA 排程仍為模擬引擎，接口已備好。
頂端列可切換**夏月／非夏月**兩個展示情境。

## 頁面

住戶有三個頁面，管理員另有「系統資訊」。

| 頁面 | 內容 |
|------|------|
| **主頁面** | 能源即時流向（含今日預估省下電費）、電池狀態、**即時運轉**（住戶：今天 00:00 到現在；管理員：過去 24 小時，每 15 分鐘往左捲一格）、**未來 24 小時預測與排程**（可切換今日全天）。管理員另有秒級重播（展示模式）、太陽能發電與不可轉移負載的預測與實際 |
| **用電規劃** | 隔日的結果摘要、電力供需與電池調度、未來 24 小時預測與排程；**用戶規劃**可選常駐排程（隔日起每天）或明日排程（只排隔日），各設備照建議、自訂範圍、指定時間或不開，按「重排」送出。**隔日的規劃在當天 23:45 截止**（日前排程在那時排定隔日），23:45～24:00 整區鎖住。甘特表上按住拖曳＝指定時間 |
| **歷史紀錄** | **單日紀錄**：當天的即時運轉曲線、原始電費與省下的電費、電費拆解、能源來源與去向、可轉移設備運轉時段、電池與天氣。**區間統計**：依日／週／月彙整，可匯出日報、月報。可看的日子是展示月 1 日到昨天，**加上比目前早的展示月整個月**（7 月時看得到整個 1 月） |
| **系統資訊**（管理員） | 帳號權限、各份資料的來源與更新時間、電池規格、電價與設備運轉規則 |

## 部署到 GitHub Pages（已設定自動化）

專案內含 `.github/workflows/deploy.yml`，**push 到 `main` 分支會自動 build 並部署**。

首次設定步驟：

1. 在 GitHub 建立一個新的 repository（例如 `hems-dashboard`）。
2. 在本資料夾執行：
   ```bash
   git remote add origin https://github.com/<你的帳號>/<repo 名稱>.git
   git branch -M main
   git push -u origin main
   ```
3. 到 GitHub repo → **Settings → Pages → Build and deployment → Source** 選擇 **GitHub Actions**。
4. 等 Actions 跑完，網址會是 `https://<你的帳號>.github.io/<repo 名稱>/`。

> 採用相對路徑（`base: './'`）與 HashRouter，所以不論 repo 名稱為何、重新整理子頁面都不會 404。

## 歷史紀錄與報表匯出

兩個分頁，只列到**昨天**——和電費帳單一樣，今天要到 24:00 才結算。

**單日紀錄**（預設）：某一天完整的運轉紀錄

| 區塊 | 內容 |
|---|---|
| 省下多少錢 | 當日電費、不裝 HEMS 的電費、省下金額與比例、用電、太陽能 |
| 即時運轉曲線 | 當天整天的太陽能、負載、電網、電池充放電、SOC，附每 3 小時天氣 |
| 電費拆解 | 尖峰／離峰各向台電買了幾度、多少錢，裝與不裝 HEMS 對照 |
| 能源來源與去向 | 家裡的電來自太陽能／電池／電網各多少；太陽能直接自用／充電池／削減各多少 |
| 設備與排程 | 各設備用電排行；可轉移設備被排在幾點運轉（時間軸 + 度數與電費） |
| 電池 | 充放電量、其中太陽能充電、等效循環次數、SOC 最高／最低與時間 |

鍵盤操作：單日紀錄按 **← →** 切換前後一天（游標在日期欄裡時不攔截）；
區間明細表的每一列可以用 Tab 選到、按 Enter 打開當日紀錄。

**區間統計**：電費帳單式，選一段日期（最多往回一年）依日／週／月彙整。

**資料來源**：系統尚未接實際電表，沒有真實的逐日量測紀錄。每個過去的日期都用
同一套模擬引擎重跑一次（依台電簡易二段式電價：夏月／非夏月、平日／假日），
算出電池、電網與電費，畫面上標示「模擬紀錄」。不可轉移負載、太陽能與天氣則取交接資料中
**同季節、同一個星期幾**那天的資料：夏月 2010-09-06～12、非夏月 2010-11-18～24，
各剛好週一到週日一天，平日／週末與季節的差異都是真的。

> 已知限制：每季只有 7 天的資料，所以同一季裡**同一個星期幾的用電量與發電量每週相同**。
> 接上實際電表後，`fetchDailyUsage()` 改讀量測紀錄即可，頁面不需改動。

一年份逐日模擬約 150 ms，切換區間時會快取已算過的日子。

匯出：
- **日報／月報 CSV**：每天／每月一列，最後附合計列；開頭帶 UTF-8 BOM，Excel 直接開中文不亂碼
- **PDF** 走瀏覽器列印（`@media print` 隱藏側欄、頂端列與按鈕，加上報表抬頭）；
  夜間模式會先暫時切到日間再印，白紙上才看得清楚

> 週末的省電費明顯較低不是錯誤：台電簡易二段式電價週末全天離峰，
> 沒有尖離峰價差，電池就沒有套利空間。日報表格中週末列以底色標示。

## 滾動預測

RF 是**滾動預測**：每 15 分鐘重跑一次、重發未來 96 步，所以同一個時刻會被
預測很多次，越接近越更新。以 2010-11-23 20:00 為例：

| 發布時間 | 領先步數 | 預測值 |
|---|---|---|
| 08:00 | 48 | 0.6305 kW |
| 12:00 | 32 | 0.6200 kW |
| 16:00 | 16 | 0.6095 kW |
| 19:00 | 4 | 0.5099 kW |
| 真實值 | — | 1.0760 kW |

UI 會重現這個行為。在第 *s* 格時：

- **過去（0～s）**：用當天**真實值**
- **未來（s+1～95）**：用「在第 *s* 格發布」的那次預測

排程與電池調度跟著重算，但只影響未來——`dispatch()` 是照時間順序推的，
過去那段吃的是不會變的真實值，所以已經發生的軌跡自然凍住，不需另外處理。

快照 `public/data/forecast_day.json` 因此包含一個 96×96 的矩陣
（`rolling[s][k]` = 第 s 格發布、領先 k+1 步），約 110 KB。

> kW 軸刻意設計成「只增不減」。滾動時每格換一次資料，若讓軸自動縮放，
> 播放時整張圖會不停上下跳，前後時刻也無法比較。

## 展示模式（期末口試用）

主頁面最上方有一條控制列。開啟後把**一天壓縮成 96 秒**播完——排程的解析度是
15 分鐘、一天 96 格，**一格對應一秒**（也可切 2×／4×）。可暫停、重播，
或直接拖進度條跳到想講的時段。

鍵盤操作（口試講解時不必回頭找滑鼠）：**空白鍵**暫停／繼續、**← →** 前後一格
（按住 Shift 一次一小時）、**Home** 回到 00:00。游標在輸入框裡時不會攔截。

做法是「換掉時鐘」而不是另外寫一套展示畫面：整個 UI 的即時區塊本來就由
`useClock()` 給的時間推導（`liveSnapshot(now)` 依 now 算出目前在第幾格，
再取該格的排程、發電、電池狀態），所以時鐘一加速，能源流向、KPI 卡、
設備開關、尖離峰電價標示、頁面二的各設備功率就會一起跑，
不會有「展示用的假畫面」和「真的畫面」兩套邏輯要同步。

日期沿用今天、只換時分，電價的夏月／平日假日判斷才不會跑掉。
「今日預測與排程」上會有一條播放頭標出目前播到哪。

實作在 [`src/lib/demoClock.js`](src/lib/demoClock.js) 與
[`src/components/DemoBar.jsx`](src/components/DemoBar.jsx)。

## 夏月／非夏月情境

頂端列的「夏月｜非夏月」切換主頁面、各負載、用電規劃三頁用的展示日：
夏月 2010-09-06（`forecast_day.json`）、非夏月 2010-11-18（`forecast_day_non_summer.json`）。
負載、太陽能、天氣一起換；電價用 `scenarioDate()` 換到該季節裡「星期幾相同」的日期去查，
所以九月也能展示非夏月的尖離峰時段。畫面上的日期與時鐘仍是真實時間，
歷史紀錄頁照每一天的實際日期計算、不受切換影響。預設跟著今天的實際季節，重新整理就回到預設。

實作在 [`src/lib/scenario.js`](src/lib/scenario.js)。

## 可轉移設備的允許運轉時段

模擬排程只看電價的話，會把洗衣機排到凌晨 00:00 開始洗。現在加上作息限制
（[`src/lib/simulate.js`](src/lib/simulate.js) 的 `SHIFTABLE_RULES`）：

| 設備 | 一次運轉 | 允許時段 |
|---|---|---|
| 洗衣機 | 1 小時 | 06:00–22:00（避開深夜） |
| 烘衣機 | 1.5 小時 | 06:00–23:00，而且要等洗衣機洗完 |
| 洗碗機 | 1 小時 | 19:00～隔天 07:00（晚餐後放進去） |

用電規劃的甘特表以斜線標出不允許的時段，那些格子不能點。

手動調整方式：在可轉移設備那一列**按住拖曳一段再放開**——按下的那一格原本關著就整段打開、
原本開著就整段關掉；只點一下（沒拖）是切換那一格。拖曳中只更新預覽，放開才重算電池調度與電費；
拖過不允許的時段會自動跳過並提示略過幾格，拖到一半按 Esc 可以放棄。手機上用手指拖曳也可以
（可編輯的格子上不會捲動畫面，要左右捲動表格請從其他列滑）。這是 UI 模擬排程的作息假設，接上 GA 後以 GA 的限制為準。

|------|------|------|
| 不可轉移負載 | MongoDB `hems.load_forecast`（RF 滾動預測，每 15 分一個 refresh × 96 步，2009-11-25 ～ 2010-11-25 一整年） | ✅ 真實 |

| 可轉移設備排程 | `simulate.js` 的最佳視窗搜尋（含允許運轉時段） | 🧪 模擬（待接 GA） |

讀不到快照時，負載、太陽能、天氣各自退回 `simulate.js`／`weather.js` 的模擬值。

### 資料庫的資料怎麼進到這個 repo

前端**不直接連 MongoDB**。MongoDB 只接受官方 driver（TCP + TLS + SCRAM），
瀏覽器發不出這種連線；Atlas 過去提供的 Data API 也已於 2025-09-30 停止服務。
更關鍵的是 MongoDB 的連線字串是一把全開的鑰匙，沒有唯讀權限層可以套，
放進前端 bundle 等於把資料庫交出去。

所以網站透過**後端唯讀 API**（見下一節）讀資料庫，另外保留一份**靜態快照**當備援。快照從 API 匯出，不需要連線字串：

```powershell
# 在 專題UI/ 底下
python scripts/export_snapshots.py      # → forecast_day*.json、history.json、schedule.json
python scripts/fetch_weather.py         # → weather.json（天氣不在資料庫裡）
```

資料庫改成 hems_db 第 2 版格式（2026-09-17，預測改存 96 個值的陣列）後，負載預測共用 repo 的 `mongo_handoff/04_export_web.py` 讀不懂新格式，不要再用它匯出。詳細說明見 `public/data/README.txt`。

資料庫更新後，重跑 `export_snapshots.py` 再 push，備援快照才會跟上；網站平常讀的是 API，不受影響。

**讀不到快照時會自動退回模擬值**，UI 不會壞掉：主頁面「今日預測與排程」右上角會標
「讀不到雲端預測，顯示模擬資料」（只缺負載或只缺太陽能時標出是哪一邊），兩張日曲線的副標題也改寫成模擬值。
讀取失敗後隔一分鐘才重試，不會每 5 秒重抓一次。

### 後端 API（hems-api）

後端唯讀 API 在 [souptomorrow-collab/hems-api](https://github.com/souptomorrow-collab/hems-api)（FastAPI，部署在 Vercel）。它直接讀 MongoDB，回傳格式和上面的快照完全相同。

- **怎麼啟用**：在本 repo 設定 Actions 變數 `HEMS_API_BASE`（API 網址，結尾不加 `/`），建置時會變成 `VITE_API_BASE`。
- **讀取順序**：
  1. 預測、歷史紀錄、排程先讀 API。
  2. API 連不上或 8 秒內沒回應，才改讀快照。
  3. 天氣不在資料庫裡，一律讀快照。
- **沒設變數時**：行為和以前一樣，只讀快照。
- **確認資料來源**：「系統資訊」頁會標出每份資料來自「API 即時讀取」還是「快照」。

本機開發要接 API：建立 `.env.local`，寫入 `VITE_API_BASE=https://…`（不會進版控）。

### 時間軸的處理

資料集是 UCI household_power_consumption（法國 Sceaux 住宅，2010 年 9 月與 11 月兩段），
時間戳是 2010 年的日期，而 UI 顯示的是當下的今日／明日。兩者這樣接：

取「23:45 發布」的那筆預測（lead 1~96 剛好是隔日 00:00~23:45，整條曲線同一次刷新、
領先步數單調遞增），再**依一日中的時段（0~95）對齊**到畫面當天。曲線形狀完全是模型的
真實輸出，只有日期標籤換掉；接上即時資料後這層對齊即可移除。

另外 RF 預測的是不可轉移負載的**總量**，拆不出各設備。頁面二的設備堆疊圖是把
各不可轉移設備按比例縮放以吻合該總量——屬於顯示用的分解，不是模型輸出（`simulate.js` 內有註明）。

| 住戶 | 主頁面、各負載功率、用電規劃（可拖曳調整）、歷史紀錄與匯出。不顯示預測模型相關的圖（太陽能預測與實際、負載滾動預測）與資料來源標示，說明文字用一般用語；天氣條放在「今日預測與排程」上方 |
| 管理員 | 住戶看得到的全部，加上預測模型圖、資料來源標示、夏月／非夏月情境切換、展示模式，以及「系統資訊」頁（帳號權限、資料快照狀態、電池規格、電價、設備規則） |

- 沒勾「保持登入」時關掉瀏覽器就登出；勾了保持 30 天。直接打開某一頁的網址（例如 `#/history`），登入後會進到那一頁。
- 住戶登入時，管理員切過的情境、開著的展示模式會恢復原狀；住戶直接輸入 `#/system` 會被導回主頁面。
- **這是前端登入，只用來區分畫面，不是資安保護。** 網站沒有後端，帳密以「鹽＋SHA-256 雜湊」寫在
  [`src/lib/auth.js`](src/lib/auth.js)：原始碼看不到密碼本身，但懂技術的人可以改瀏覽器儲存的登入狀態繞過，
  `public/data` 的資料檔也仍能直接下載。不要拿真的在用的密碼來設定。
- 修改或新增帳號：`npm run hash-password -- <帳號> <密碼>`，把印出的那一行貼到 `ACCOUNTS`（role 填 `resident` 或 `admin`）。

## 無障礙與穩定性

- **對比度與標籤**：以 axe-core 檢查 WCAG 2 A/AA，四頁 × 日間／夜間 × 桌機／手機，
  另外含展示模式、非夏月情境、區間統計，目前 0 違規。白字按鈕用 `--accent-solid`、數字卡的數字用文字色
  （能源色只放在標題前的小色塊），改顏色時留意不要退回太亮的底色。
- **鍵盤**：每頁按 Tab 第一下會出現「跳到主要內容」，Enter 後直接進內容區、不必先走過整排導覽
  （用按鈕而不是 `#main` 連結，因為網站用 HashRouter，`#` 後面是路由）。
  展示模式（空白鍵、← →）、單日紀錄（← →）、區間明細表（Tab＋Enter）、
  手機上可左右捲動的甘特表都能用鍵盤操作；焦點一律有外框（`:focus-visible`，日期欄用 `:focus`）。
- **資料壞掉時**：快照讀不到會退回模擬值並標示；資料欄位格式不對時（例如日期變成數字、天氣少欄位）
  跳過那筆或改用模擬天氣；真的遇到沒預料到的繪製錯誤，`ErrorBoundary` 只讓那一頁顯示錯誤說明，
  側欄與其他頁照常可用。

## 圖表的幾個約定

- **功率與 SOC 分成上下兩格**：SOC（%）不和 kW 共用一張圖的左右兩條 y 軸——兩把尺各自縮放，
  SOC 曲線會穿過放電的負值長條，看起來像 SOC 變負的。改成上面功率、下面 SOC 小圖，
  x 軸對齊、十字線連動（`src/lib/charts.js` 的 `powerSocLayout()`）。
- **區間統計的電費另開一張**：kWh 與元不放在同一張圖。
- **圖例圖示跟著系列種類**：折線畫成線、長條畫成方塊。
- **設備配色**：最多 8 組，取自色盲辨識度驗證過的順序，分日間／夜間兩組（`src/lib/constants.js`）。

```
scripts/
  fetch_weather.py     ← 抓展示日期的台北 ERA5 天氣

public/data/           ← 匯出的快照（見 README.txt）

  api/
    client.js          ← 資料存取層（換後端只改這裡）
    forecastData.js    ← 讀 public/data/ 的快照（負載、太陽能、天氣）
  lib/
    constants.js       ← 時間解析度(15min)、電池、設備、圖表分組與配色
    scenario.js        ← 夏月／非夏月情境切換
    tou.js             ← 台電時間電價
    simulate.js        ← 能源模擬引擎（排程、允許運轉時段、電池調度）
    weather.js         ← ERA5 天氣轉換（讀不到時的模擬天氣）
    charts.js          ← ECharts 共用設定與主題
    dayRecord.js       ← 單日紀錄的彙整
    demoClock.js       ← 展示模式的虛擬時鐘
  hooks/               ← useClock / useMediaQuery
  components/          ← Layout / Panel / StatCard / Tile / EChart / EnergyFlow / WeatherStrip / DemoBar /
                         ErrorBoundary（某一頁出錯時只有那一頁顯示錯誤說明，側欄與其他頁照常可用）
  pages/               ← Dashboard / Loads / Planning / History
```
